# Redlinelabs Website Health

Last Updated: 25 September 2026

Overall Status: The live site at https://redlinelabs.shop/ is up, Stripe live checkout is configured, and the main catalogue pages return 200. This branch closes a checkout integrity hole and corrects customer-facing claims that the browser account cannot fulfill. That fix is not on production until it is reviewed and deployed. The current design system is Redline Labs black and gold. It was left in place.

## Critical Issues

1. Checkout accepted a store-credit amount from the browser and created a Stripe coupon for it. Account balances exist only in `localStorage`. There is no server ledger, and `grantStoreCredit` is not called by the storefront, so a client-supplied amount could reduce the card charge. Fixed on this branch: `serverStoreCreditCents()` always returns 0, the checkout server action no longer accepts a credit amount, and the checkout summary no longer subtracts a browser balance from “Due now”. Production still has the old behaviour until this change is deployed.
2. The live checkout path (`startCartCheckoutSession`) did not require the age and research-use checkboxes. The UI collected them, then the server action created a session with those flags hardcoded. The action and `createEmbeddedCheckoutSession` now reject a session unless both confirmations are true.

## High Priority Issues

1. Production is behind this repository. `GET /product/bacterial-water` returns 404 on https://redlinelabs.shop/, and that URL is absent from the live sitemap. The product is in `src/data/products.json` and is generated by the local build (commit `55a0dc1`, 24 September 2026). The homepage cache `age` was about 4.5 days at the time of this audit. Do not treat a new production deploy as part of this change unless it is explicitly requested.
2. Accounts are a browser profile, not a customer system. Sign-up, passwords (salted SHA-256), orders, addresses, store credit, and stock alerts are stored in `localStorage`. There is no Stripe webhook. Order history is written only if the success page loads in that browser. Tracking numbers are never filled from a carrier. A different device has an empty account.
3. Customer copy promised behaviour the site does not perform: automatic store-credit deductions, and restock emails (“we will ping you”). Account, FAQ, checkout, and the product restock control now describe a device-local watchlist and a balance that is not deducted from the card charge.
4. `GET /api/checkout/session?session_id=cs_…` returns email, shipping address, and line items to anyone who has the Checkout Session id. The success URL puts that id in the query string. Response headers do not set `Referrer-Policy`.
5. No product analytics or error reporting is implemented in this repo. The production HTML preloads `https://assistloop.ai/assistloop-widget.js`, so AssistLoop is enabled in the live environment. An open draft pull request exists for Vercel Speed Insights (`#22`). The privacy policy says the site may use cookies and analytics.
6. Product JSON-LD marks every listing `InStock`. There is no inventory source. FAQ content has no `FAQPage` schema. Several slugs are legacy WordPress paths (`products-dsip`, `product-tb-1`) and one is misspelled (`products-kisspepien`). Renaming them needs redirects.

## Medium Priority Issues

1. Catalogue photos are remote files on `i0.wp.com` / `redlinelabs.shop`. `ProductImage` falls back to `/brand/vial.png` if a photo fails. A sampled BPC-157 image returned 200 during this audit.
2. Security headers on the live homepage are limited to HSTS from Vercel. No `Content-Security-Policy`, `X-Frame-Options`, or `Referrer-Policy` was present. The homepage also sends `Access-Control-Allow-Origin: *`. A strict CSP needs a Stripe Embedded Checkout allowlist before it is added.
3. Contact is a `mailto:` composer. The newsletter form tells the visitor it does not start a mailing list. Both are honest, and neither captures a lead server-side.
4. Dead or unused code: root `index.mts` (AI SDK demo, only consumer of the `ai` dependency), `src/components/Placeholder.tsx`, default `public/*.svg` files, and unused `public/brand/hero.png` and `public/brand/logo.png`.
5. `npx tsc --noEmit` fails with `Cannot find name 'LayoutProps'` until `next build` has generated `.next/types`. `next build` itself typechecks successfully.
6. Node’s test runner warns that `package.json` has no `"type": "module"` (`MODULE_TYPELESS_PACKAGE_JSON`). Tests still pass.
7. Listing titles mix case (`BACTERIAL WATER`, `BPC-157`, `Semax`). Categories in code are consistent with the data file. All nine shop categories have at least one product. The catalogue has 30 products.

## Low Priority Issues

1. Checkout coupon `DGC20` (20% off the order total) is a public code in source. Promo lookup is server-side and rejects unknown codes. Prices charged by Stripe come from the catalogue, not the browser cart.
2. `stripe-keys.ts` scans every environment value for a Stripe key shape, then prefers a live key when `VERCEL_ENV=production`. That is intentional for hosted key injection. Test keys are ignored on production.
3. `GET /api/checkout` reports whether live keys are configured and returns the publishable key. The publishable key is meant to be public. The response checked on production was `configured: true`, `mode: live`. The key value is not recorded in this report.

## Changes Made

- Checkout no longer turns a browser store-credit balance into a Stripe coupon.
- Checkout requires age and research-use confirmation on the server action and on `POST /api/checkout` before creating a session.
- Checkout, account, FAQ, and the product restock control now match that behaviour.
- Added `reports/website-health.md`.
- No visual redesign. Header, gold/black palette, catalogue data, and DGC20 coupon behaviour are unchanged.
